# Spec: extract-the-merge-protocol

**Slice:** `extract-the-merge-protocol` — kind `enabler-process`, ruled by the user 2026-09-17.
**Author:** `coach`, SPEC mode, 2026-09-17. **Executor:** `writer`, after the user signs off.

This is the tree's first `spec.md`, so it also settles the section shape a `coach` spec takes —
the open question `staff-the-enabler-process-pipeline`'s design left to it. The shape is
`design.md`'s, which is already the per-item artifact convention: `name`/`title`/`created`
frontmatter, then the body, closing with `## Touches` and `## Open questions`. A spec adds the
file-by-file edit list and the check-reading table its own role file mandates.

## The impediment

CLAUDE.md is auto-loaded into every session and every subagent. Its merge-protocol section is
**18,657 of its 89,387 bytes — 20.9 percent**, measured on this slice's branch point. One audience
executes it: the orchestrating seat, and only while landing a slice. Every other reader pays for it
on every invocation.

Routing branch 1 put it there deliberately, and that branch is still right about the general case.
So this spec does not delete the branch. It writes the exception into the branch text, states the
test that bounds the exception, and leaves in CLAUDE.md exactly what binds **before** the protocol
starts.

## The ruling: what stays, and the test behind it

**A fact that binds before step 1 stays in CLAUDE.md. A fact that binds inside the protocol moves.**

A reader already executing step 3 has the file open, so a mandate restated in CLAUDE.md buys nothing
and costs a second copy. The mutation-invariance allowlist is the precedent: it lived in CLAUDE.md,
`mutation-testing.md` and `hardener.md` at once, and the three drifted apart.

That test settles open question 1 as follows.

| Candidate                              | Ruling | Why                                                                          |
| -------------------------------------- | ------ | ---------------------------------------------------------------------------- |
| The serial-landing rule                | Stays  | It decides how many slices the seat starts, before any merge begins          |
| A pointer, with a read-at-step-1 order | Stays  | A skipped step reads exactly like a passed one, so the trigger must be loud  |
| The step-3 and step-5 gate mandates    | Move   | They bind a reader who has the file open; a copy here is the drift precedent |
| The mutation-invariant exemption       | Move   | Same, and it is the largest single block                                     |
| The perf-run procedure                 | Move   | Whole-section move; see file 1                                               |

**Open question 2 is settled: verbatim move, no split, this slice.** The clause-level reasoning
travels unchanged into `merge-protocol.md`. A move plus a rewrite cannot be reviewed as a move —
`editor` AUDIT and `coach` REVIEW would have nothing to diff against. Splitting the reasoning into
the sidecar is a later `enabler-process` item, recommended in the handoff.

**Open question 3 is settled by measurement, not by reasoning — see "Verification already run".**
