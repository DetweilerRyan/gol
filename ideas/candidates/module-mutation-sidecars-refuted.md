## Do not build this

This was proposed, examined against the tree, and refuted before any file was written. It is kept
because the idea is plausible enough to be re-proposed, and the reasons it fails are measured rather
than aesthetic.

**The proposal.** Give each module a third sidecar, `<module>.mutation.md`, holding its mutation
survivor rulings. The argument was that such rulings sat in `mutation-testing.rationale.md`, that
`hardener` had to already know that file existed and grep it, and that a tier whose read trigger is
generated by a tool — Stryker names a file — deserved its own home.

## Why it fails

**1. The rulings are not in the article. They are already at their sites.** Measured 2026-09-10:
**fourteen files carry one**, eight under `src/` and six under `scripts/`. `mutation-testing.md`
prescribes exactly that, and `slice/equivalence-rulings-live-in-commits-not-at-sites` implemented it,
moving six rulings **out of commit messages and onto the sites themselves**. The premise that they
are homeless was simply false.

**2. A file is the form the repo already rejected.** That slice's reason is recorded in
`mutation-testing.md`: a site comment _"is also the artifact a later reader can check, which a triage
note in a commit message is not."_ A `.md` file is the same out-of-band shape as the commit message,
one directory further from the code.

**3. It would silence a forcing function.** `mutation-testing.md` sets a two-line budget on an
equivalence argument, and says the corollary is the useful half: _"an argument that doesn't fit in
two lines is not comment material, it is a warning."_ The warning is a signal to write a test or find
a counterexample. **A file has no budget**, so the signal stops firing and the long unresolved
arguments the rule exists to catch would simply be accommodated.

**4. The discoverability argument inverts on inspection.** Stryker reports a file **and a line**, and
the ruling is on that line. A per-module file is strictly further away than the thing it would
replace. The original argument counted only half of what Stryker reports.

**5. The article's mutation content is organised by mechanism, not by module.** Its sections are the
`NoCoverage` correction, the covered-but-undiscriminated case, the statement-removal mutator, the
suppression-idiom ruling — each using a module as its worked example. Splitting those per module
would fragment repo-wide arguments into partial accounts filed under one component.

Both tables in `mutation-testing.rationale.md` confirm this. One measures a **documentation split**
(article bytes, entanglement 92% → 71%). The other rules on an **idiom**, comparing `it.skipIf`
against `// Stryker disable`, where `Grid.tsx` 23/23 versus **0 of 23** is the measurement vehicle.
Filing that under `Grid.tsx` would hide a repo-wide trap — file-scope suppression silently zeroing a
mutant count — inside one component's sidecar.

## The tier question it was really asking

The candidate's own first open question was whether three per-module tiers are too many, given that
two were justified on _using versus changing_.

**The third tier exists and is not a file. It is the comment at the site.** `<module>.md` is read by
whoever is calling, `<module>.rationale.md` by whoever is changing, and a mutation ruling by whoever
is looking at that exact line — which is why it belongs on the line.

## What would change this

Not much, and it is worth stating so a future reader can check rather than re-argue:

- **If site comments stopped being checkable.** The whole case rests on a comment being an artifact a
  reader can verify against the code beside it. Nothing currently threatens that.
- **If a staleness checker were built and could not work against site comments.** The original
  candidate's strongest point was that a ruling can go stale mechanically, and that a separated tier
  makes "does every ruling still name a live survivor" answerable by a program. That question is
  real and survives this refutation — but it argues for a **checker over the site comments**, not for
  moving them. Anyone reaching for that should read `mutation-testing.md`'s two-line budget first,
  since a checker that encourages longer arguments would cost more than it catches.

## Touches

Nothing. No file was created, and none should be.
